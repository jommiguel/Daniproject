Aprendizagem passo a passo

          
Aprende a construir. Não apenas a copiar.

          

            Escolhe o teu assistente, segue os passos e copia os prompts. Cada
            tarefa inclui o que fazer, o que deves ver e o que fazer se falhar.
            Não precisas de saber programar antes de começar.
          

          

            

              AULA 01
              
O que são Git, GitHub, VS Code e IA?

            

            

              VS Code é a secretária onde editas os ficheiros.
              Git é o histórico das alterações.
              GitHub guarda uma cópia online desse histórico.
              Claude Code ou Codex são assistentes que podem
              ler e propor alterações ao código, dentro das permissões
              disponíveis.
            

            

              Exemplo: pedes um formulário de tarefa → a IA
              propõe código → tu verificas o resultado → guardas uma versão com
              Git → envias para o GitHub. A IA não substitui a verificação.
            

          

          

            

              AULA 02
              
Instalar e verificar as ferramentas

            

            
    
              
  1. 
                Abre os links oficiais de
                VS Code,

                Escolhe a versão para o teu sistema operativo.
              
    2. 
              
  2. 
                Instala as aplicações seguindo o instalador. Fecha e volta a
                abrir o VS Code.
              
    3. 
              
  3. 
                No VS Code, escolhe Terminal → New Terminal e
                executa os comandos seguintes, um de cada vez.
              
    4. 
            

            

              git --version node --version npm --version
            

            

              Resultado esperado: cada comando mostra um número
              de versão. Se aparecer “command not found”, verifica a instalação
              e reinicia o terminal. Não copies comandos aleatórios de fóruns
              sem perceber o que fazem.

              AULA 04
              
Claude Code ou Codex: qual é a diferença?

            

            

              Ambos ajudam a compreender, planear, escrever e rever código. O
              Claude Code é um agente de programação da
              Anthropic; o Codex é um agente de programação da
              OpenAI. O acesso e a instalação dependem da plataforma, versão e
              conta. Segue sempre a documentação oficial atualizada.
            

            

              Documentação oficial Claude Code
              ·
              Documentação oficial Codex
            

            
    
              
  1. Escolhe um dos dois. Não precisas de instalar ambos.
    2. 
              
  2. 
                Segue o guia oficial de instalação e autenticação. Nunca
                partilhes passwords, tokens ou chaves no chat.
              
    3. 
              
  3. 
                Abre a pasta primeiro-projeto no VS Code e inicia o
                assistente no contexto dessa pasta, conforme a ferramenta
                escolhida.
              
    4. 
              
  4. 
                Começa por um pedido apenas de leitura: o
                assistente deve explicar o projeto antes de alterar ficheiros.
              
    5. 
            

            

              Cola-o no Claude Code ou Codex.
            

            

              Regra de ouro: lê as alterações propostas,
              confirma o que o agente vai executar e pede explicações para
              comandos que não compreendes.
            

          

          

            

              AULA 05
              
O primeiro pedido que cria valor

            

            

              Não peças “faz-me uma aplicação perfeita”. Começa por um objetivo
              pequeno, verificável e com critérios de aceitação.
            

            

              Quero construir uma aplicação simples chamada Gestor de
                Tarefas. Objetivo: registar tarefas do dia a dia e acompanhar o
                estado de cada uma. Tecnologias: HTML, CSS e JavaScript vanilla,
                sem backend nem dependências. Primeira tarefa: cria apenas a
                estrutura inicial com index.html, styles.css e app.js. Antes de
                alterar ficheiros: 1. Explica o plano em 5 pontos. 2. Diz-me
                quais os ficheiros a criar. 3. Indica como testar no navegador.
                4. Espera pela minha confirmação. Usa português de Portugal,
                código legível e design mobile-first.
            

            
            

              Como validar: abre index.html no
              navegador, verifica se não há erros na consola e confirma que a
              página se adapta ao telemóvel.
            

          

          

            

              AULA 06
              
Melhorar a aplicação

            

            
    
              
  1. 
                Funcionalidade: adicionar, editar e apagar
                tarefas, mudar o estado e filtrar resultados.
              
    2. 
              
  2. 
                Persistência: guardar no
                localStorage, explicando que os dados ficam neste
                navegador e podem desaparecer se o armazenamento for limpo.
              
    3. 
              
  3. 
                Qualidade: validar campos, mostrar mensagens de
                erro úteis e impedir duplicações acidentais quando fizer
                sentido.
              
    4. 
              
  4. 
                Design: tokens de 4/8 px, contraste, estados de
                foco, layout mobile-first e zero decoração gratuita.
              
    5. 
              
  5. 
                QA: testar com lista vazia, texto longo, erros,
                teclado, 320 px e dados fictícios.
              
    6. 
            

            
          

          

            

              AULA 07
              
Guardar alterações e publicar

            

            

              Depois de testares, abre Source Control no VS
              Code, revê os ficheiros alterados, escreve uma mensagem clara como
              feat: adicionar formulário de tarefas, faz
              Commit e depois
              Push / Sync Changes.
            

            

              Para um site estático, podes publicar em
              GitHub Pages nas definições do repositório:
              Settings → Pages → Deploy from a branch → main / root →
                Save, quando essa opção estiver disponível. Aguarda pela publicação e
              testa o URL em janela privada.
            

            

              Antes de publicar: remove dados pessoais,
              credenciais, chaves e qualquer informação que não devas expor.

Como estudar um vídeo sem ficar só a ver?

            

              Faz uma pausa após cada demonstração, repete no teu computador,
              escreve o que mudou e tenta explicar em voz alta. Se falhares,
              identifica o passo exato antes de pedir ajuda à IA.
